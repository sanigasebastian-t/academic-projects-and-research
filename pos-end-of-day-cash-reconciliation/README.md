# POS End-of-Day Cash Reconciliation Testing

## Project Overview

This individual academic project focused on black-box functional testing of a Point of Sale (POS) end-of-day cash reconciliation process.

I created a web-based demonstration application using HTML, CSS and JavaScript to simulate the cash reconciliation workflow. I then designed and executed functional test cases to verify the application's calculations, validation rules and expected behaviour.

## Project Objectives

- Apply black-box testing techniques to a practical business scenario.
- Identify expected system behaviour from functional requirements.
- Design test cases covering positive, negative and boundary scenarios.
- Verify cash calculations and reconciliation outcomes.
- Explore browser test automation using Selenium WebDriver and pytest.

## Application Features

- Opening cash float and cash sales entry.
- Cash-in and cash-out adjustments.
- Cash denomination and quantity entry.
- Automatic expected cash and counted cash calculations.
- Identification of balanced, shortage and overage outcomes.
- Reconciliation closure validation.

## Testing Approach

Black-box functional testing was used to evaluate the application's behaviour based on inputs and expected outputs, without examining its internal implementation.

Testing covered scenarios such as:

- Balanced cash reconciliation.
- Cash shortage and overage.
- Different cash denominations and quantities.
- Calculation accuracy.
- Input validation.
- Reconciliation closure conditions.

## Test Automation

Selenium WebDriver and pytest were used to explore automation of selected functional test scenarios through browser interactions and result verification.

## Technologies Used

- HTML, CSS and JavaScript
- Python
- Selenium WebDriver
- pytest

## Key Learning Outcomes

- Applying black-box testing principles.
- Translating functional requirements into test cases.
- Validating expected and actual results.
- Testing positive, negative and boundary scenarios.
- Exploring automated web application testing.

## Project Scope

This demonstration focuses on the end-of-day cash reconciliation workflow. It is not a complete POS system and does not include payment processing, inventory management, user authentication or database integration.
